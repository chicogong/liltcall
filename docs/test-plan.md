# 测试方案与指标

更新：2026-09-23。公网自建 coturn、Worker 短期凭据及网页已部署；同机假设备的公开站点强制 relay 和正常 direct 均通过。随后一次 Mac 模拟设备房主 ↔ 用户手机通话选中 `relay`，用户确认手机有声音、有画面；用户此前报告使用 iPhone Chrome/蜂窝数据，本次未重新核验。**这仅验收了手机侧接收，尚未完成双向真人音视频验收**。音频和视频共用同一选中 ICE 路径，可能直连也可能经 TURN 中转；STUN 只协助发现地址。指标为发布门槛；本地自动化、真实设备和云端观测必须分开报告，不用单次成功代替可靠性结论。

| 层 | 方法 | 当前/目标覆盖 |
|---|---|---|
| 协议单测 | Vitest，固定时钟、纯状态函数 | 创建→加入→满员/关闭/过期；令牌身份与消息白名单 |
| API/WSS 集成 | 本地 Wrangler，独立会话和 WebSocket 客户端 | 未授权/重复加入/票据重放/跨房间/关闭后请求均拒绝；非对象 JSON 被关闭，后续有效票据仍可认证 |
| 浏览器 E2E | Playwright 两个独立 context、fake camera/microphone | 英文/简体中文建房→邀请→双向音视频 RTP、视频帧解码→静音/关开摄像头→结束；无密钥时 STUN-only、TURN 配置校验与可接受性、摄像头拒绝后语音降级、刷新重入及旧 ICE 返回竞态、信令恢复、自动播放重试、存储/音量表故障、短屏布局与语言切换。本机和公开站点强制 relay 均通过；真机异网未覆盖 |
| 真实网络 | iPhone Chrome/WebKit ↔ Mac Chrome、Wi-Fi ↔ 蜂窝、异运营商/受限网络 | 一次用户手机的音视频接收与 relay 选路通过（网络类型未重核）；待双向人工可听/可见、更多网络与匿名 ICE 诊断，全部路径失败才显示失败 |
| 安全与成本 | 授权矩阵、限流/滥用压力、日志审查 | 公开部署前阻断；AI 独立模式需另设成本上限 |

## 可计算指标

| 指标 | 起止事件 / 采集方法 | M1 本地门槛 | M2 公网门槛 |
|---|---|---|---|
| 建连成功率 | 受邀者点击加入至双方 `connectionState=connected` 且 inbound audio/video RTP 包数增长；摄像头关闭的语音场景单列 | 20/20 次 | 每类网络 20 次；按 direct/relay/失败分组，不拿掉失败样本 |
| 首 RTP 观察时间 | 来宾点击加入至该端首次在 `getStats()` 观察到 inbound audio RTP；房主另从 `peer-joined` 计时，不计等待来宾的时间 | p95 ≤5 秒；注明采样间隔 | p95 ≤10 秒；双方分别统计 |
| 信令重连 | 人为断开 WSS 至两端再次完成 `ready` | p95 ≤3 秒（目标，尚无本轮分位数证据） | p95 ≤8 秒 |
| 媒体恢复 | 切换网络/ICE failed 至 inbound 包数再次增长 | 记录，不作为本地 CI | p95 ≤15 秒；失败逐例归因 |
| 房间权限 | 越权、旧票据、第三人加入、关闭/过期链接 | 0 次越权成功 | 0 次越权成功 |
| TURN 回退与标识 | ICE API 只对已验证成员返回短期凭证，长期 key 不出 Worker；信令可传 relay candidate/SDP；通过 `transport.selectedCandidatePairId` 识别实际 pair，本地或远端 candidate 为 relay 则显示中转 | 授权/凭证/配置单测、本地直连、本机 coturn 强制 relay 双向媒体通过；公开站点同机强制 relay 也通过 | 强制 relay 对照 + 正常 ICE 两组均双向音视频成功，并正确标注路径；不能仅凭候选存在判定已中转 |
| 视频有效性 | 双方 `inbound-rtp` 的 video 包增长、`videoWidth > 0`、可见画面及关开摄像头后恢复 | 自动化全通过 | 双方人工看见且画面持续更新，记录黑屏/卡顿 |
| 音频质量 | 人工双向可听、丢包/抖动/RTT 来自 `getStats()` | 保存诊断，不设伪精度阈值 | 每类网络记录 p50/p95 与失败样本 |

分母包含超时与用户可重试但失败的会话；将“拒绝麦克风权限”单列为用户行为，不计作 WebRTC 建连失败。每次真实网络样本记录浏览器/OS、网络类型、时间、选中 candidate pair、耗时与错误层；不采集原始音视频。当前未连通时约每秒采样一次 `getStats()`；连通后首次 RTP 前约每 200 ms 采样，随后约每秒一次。连接详情仅在本机显示选中 ICE 候选对的当前 RTT，以及当前接收流的语音/视频收到包数、累计丢包数、抖动与视频卡顿数（浏览器支持时）；缺失或无效值显示“—”，不能当作 0。若 `getStats()` 缺选中候选对 ID，网页尝试浏览器 ICE 传输层的已选候选对；两者都不可用则显示“路径统计不可用”，不可根据出现过的 relay 候选猜测路径。切换流或重连可能使累计值清零，不跨连接相加。不要把累计丢包数直接当丢包率；同一端不同时间的收包/丢包增量才可供估算，也要注明浏览器统计口径。“首 RTP”是首次观察值，至少有采样与调度误差，不是人耳听到声音的口到耳延迟；ICE RTT 也不能替代口到耳测量。若需验收体感延迟，应两端进行真人对话并另做同步声画测量，分开报告。p95 只在样本量足够时报告，同时提供样本数与原始失败数。

每类网络 20 次是早期故障发现门槛，不足以在统计意义上证明真实成功率 ≥95%；即使 20/20，单侧 95% 置信下界也仅约 86%。对外声称可靠性之前扩大样本并明确置信区间，例如零失败时约 60 次独立呼叫才刚达到 95% 的单侧下界。连续重试并非完全独立样本，应跨设备、时段和网络采样。

下一轮两台真机验收建议每通保持至少 60 秒：来宾点击加入时起计，双方分别确认能听到真人说话、看到持续变化的真人画面；在接通后约 10、30、60 秒记录两端连接详情中的路径、ICE RTT、语音/视频抖动与累计丢包、视频卡顿，另记录网络类型与有无 VPN。不要保存邀请链接、候选地址或原始音视频。若选中 relay 且两端 RTT 持续偏高，优先检查中转路径与节点地域；若 RTT 尚可而抖动/丢包上升，优先排查接入网络；若这些指标正常但听感仍慢，另查采集、编码、抖动缓冲和播放链路。以上只是定位顺序，不用单次读数推出唯一根因；改 TURN 地域、码率或分辨率前先保留基线并做相同网络的对照。

## 手工矩阵与步骤

1. 先确认 Worker 已配置全新 coturn 共享密钥、`/ice-servers` 对已验证成员返回 `relay_allowed` 且含有短期 TURN 凭证；未授权返回 401，响应不可缓存，日志不含凭证。两台设备打开同一部署，分别位于同 Wi-Fi、Wi-Fi↔蜂窝、异运营商、公司/校园网络；每类至少 20 次新房间，并保留失败样本。
2. 每次确认摄像头/麦克风授权、双方可听可见，记录上表时间和 `getStats()`；不能用“UI 显示已连接”代替实际媒体证据。
3. 用测试专用浏览器配置把 `iceTransportPolicy` 设为 `relay`，完成一轮双方接收音视频的强制中转对照；双方 selected pair 必须显示 `relay`，否则停止上线。正常配置 `all` 再测同网与异网，记录 direct/relay；ICE 可能并行检查候选，不承诺任何成功直连都一定优先于 relay。旧 `?ice=relay` 参数仍不得改变产品策略或进入邀请链接。
4. 在等待、通话中和断线窗口分别测试刷新、关闭标签、房主结束、来宾离开、网络切换、权限撤销。
5. 用第三浏览器持有邀请链接、错误/过期票据测试满员和越权；检查旧链接绝不复活房间。
6. 两端分别设为英文和简体中文复测入会前、等待、通话、失败、结束文案；检查手动切换后 `html[lang]`、页面标题、控件可访问名称、刷新持久化和短屏首屏可操作性。语言偏好只留在各自浏览器，不写入邀请链接。
7. 针对本次 Mac Chrome ↔ iPhone Chrome 异网失败：新建一个房间，Mac 与 iPhone 使用不同网络，确认两端均显示“信令已就绪”；通话成功须双方实际听见/看见对方，并记录各自显示的 `direct` 或 `relay`。若失败，分别打开“连接详情”，记录 ICE 状态、本地/远端局域网、公网与中转候选事件数、探测请求发/收及回应发/收、ICE 服务/候选错误数、重试数；“—”代表浏览器未提供该统计，不能当 0。截屏时遮住邀请链接、房间路径和个人信息。若某端中转候选为 0，先查凭证签发、TURN 地址/端口可达性；这些只是定位线索，不能仅凭计数判定唯一根因。
   新版连接详情还显示浏览器当前统计中的候选对数与远端候选数；把它们和候选**事件**数一起记录，避免把“信令已收到候选”误当成“候选已形成 ICE 检查对象”。ICE restart 后当前统计可能清零，不能跨快照直接相加。

## 发布停止条件

任一授权绕过、房间关闭后仍可入会、长期 TURN 密钥泄漏、未授权签发短期凭证、选中路径被误标、公开部署没有限流/资源保护，或目标网络的异网双向音视频未通过门槛，均停止正式开源推广。已部署 coturn 有并发、带宽、CPU 和内存上限；仍应监控服务健康、到期续费及资源占用。现有按 IP/位置限流不是全球硬上限。仅当 M1 本地与 M2 真实设备公网分层证据完整，才把 README 状态改成“真机异网已验收”。

AI 模式另设指标：首段 TTS 音频、打断生效时间、误触发、并发成本、撤销授权后媒体停止时间；在选定 SFU/模型并建立基线前不伪造数值目标。
