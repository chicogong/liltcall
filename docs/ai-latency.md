# AI 语音延迟：定义、现有证据与复测方法

更新于 2026-09-24。这里仅讨论独立、私有的一人 + AI 语音原型，不代表已部署的双人通话。历史样本来自 `cloud` 整段模式；另有[尚未真实服务商验收的 `cloud-stream` 模式](ai-streaming.md)，不能复用这些耗时。

## 现在能回答什么

| 指标 | 已有单次样本 | 不能推论什么 |
|---|---:|---|
| 腾讯云 ASR 整段请求 | 本机 0.63 秒；服务器 0.84 秒 | 不含 VAD 等待、上行 WebRTC；不是流式识别首字 |
| 硅基流动 LLM 整段文本请求 | 本机 1.14 秒；服务器 2.53 秒 | 非语音流水线里的首段文本；样本只有一次/环境 |
| 腾讯云 TTS 整段 PCM 请求 | 本机 1.42 秒；服务器 2.58 秒 | 不含 RTP 下行或扬声器播放；不是流式首音频 |
| 浏览器点击连接至测试观察回复 | 本机约 6.69 秒；远端约 94.3 秒 | 含建连、假麦克风与轮询；远端用例有 60 秒静音尾部和两轮分段，不能当口到耳或首包延迟 |

以上分别来自[历史测试记录](test-results.md)和[私有服务器记录](ai-private-stage-2026-09-24.md)，不是本次改动后重新调用服务商所得。没有可比较的真实用户“说完 → 听到第一个音频包”的 p50/p95，也没有已验证的远端 LLM 首段文本时间。不要把三个独立 API 样本简单相加称为通话总延迟。

## 新增的计时点

云模式的 `/api/metrics/{peer_id}` 与私有页面现在展示**最近一轮**的内容无关计时（毫秒，未观察到显示 `—`）：

- `stt_request_ms`：开始腾讯云一句话识别调用，到 SDK 返回。语音必须先经 VAD 分段；这段等待不在数值内。
- `llm_first_text_ms`：Pipecat 向 LLM 发送上下文，到下游首次看到文本帧；是流水线首段文本，不保证等于模型首 token。
- `llm_total_ms`：同一上下文帧到 LLM 完成帧；这是流水线观察值，不是供应商控制台计费耗时。
- `tts_request_ms`：首次 `TextToVoice` 调用到完整 PCM 收到并解码。当前接口一次返回整段音频，不能称为流式 TTS 首包。
- `llm_to_first_audio_ms`：LLM 上下文帧到服务端第一帧输出 PCM；包含 LLM、文本积累、TTS 与本机流水线调度。
- 浏览器“点击至首次观察到入站 RTP”：点击连接到 `getStats()` 首次看到非零入站音频包；约每 500 毫秒采样，还可能受诊断 HTTP 请求影响。这是带采样误差的浏览器侧观察值，**不是音频包真实到达时间或人耳听到的时间**。

服务端只公开整数计时和既有计数，不保存麦克风采样、转写、LLM 输出或密钥。客户端和服务器各用自己的单调时钟，不跨机器相减。挂断后原有指标随连接删除。若出现打断或重叠轮次，最近一轮字段可能来自不同处理阶段；当前测试只用单人、单轮/顺序轮次，不能把该结构用于生产级并发归因。

## 可复现的延迟测试方案

1. 先用不触发服务商的 Python 合同测试、类型检查、无模型浏览器探针验证计时和 WebRTC。浏览器测试用 Playwright 状态/计数断言，不用固定睡眠推断“已收到声音”。
2. 真实云测试前，人工确认腾讯云 ASR/TTS 可用额度和后付费状态、硅基流动余额，并限定单轮与总调用预算。普通 CI 永远不调用真实服务商。
3. 用固定音频、固定句长、同一机房/网络分别做冷启动与预热后的单轮测试；记录服务器阶段值、浏览器首次 RTP 观察值、VAD 起止、连接用时、ICE 选路与失败数。单次通过只证明链路，至少 30 个**事先批准预算**的样本才能报告 p50/p95，并同时报告样本量、设备、网络、冷/热状态和失败率。
4. 真实 iPhone 蜂窝网络另做端到端验收，并用受控音频时标测“说完 → 扬声器实际发声”。`getStats()` 与 ICE RTT 均不能代替这个指标。

旧模式最大的已知结构性延迟是“等一句话结束 → 整段 ASR → LLM → 整段 TTS”，尤其 `TextToVoice` 不边生成边播放。新 `cloud-stream` 模式已实现实时 ASR、SSE LLM 和增量文本/音频 TTS 的协议桥接，但尚无真实账号性能数据；其 ASR 指标改为“本机 VAD 说话结束 → 稳定句段”，TTS 指标改为“首段文本发送 → 首块 PCM”。还需验证断网、打断及用户口到耳；优化前后必须在相同设备和费用边界下比较，不能用独立 API 耗时冒充用户感知延迟。

2026-09-24 延迟调参：腾讯云实时 ASR 静音阈值从 700 ms 调到 600 ms；TTS 在较长分句的逗号处使用服务商支持的断句符，离线模拟证明可以在 LLM 完成前交付音频。前者只是**配置的静音窗口缩短 100 ms**，不是测得的整链路收益；后者的真实音色、听感和首包收益仍待同条件 A/B 验证。Pipecat 的帧处理器之间使用队列，因此 TTS 握手已可与 LLM 请求重叠，不把另起后台握手任务当作优化成果。
